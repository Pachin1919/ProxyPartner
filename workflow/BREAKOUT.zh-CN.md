# Loop 的 breakout 规则

breakout 指退出当前修复循环，转到重新规划、等待所需输入或正常结束；不是删除失败证据，也不是自动换更贵模型。规则由协调者执行，LangGraph 负责明确路由。默认参数见 orchestrator.policy.json。

## 失败计数
failure signature = task + check ID + 根因分类。初次验证失败后允许最多两次针对同一根因的修复；第二次修复仍失败即进 replan。保留原失败、两次 diff/假设/测量；改错误文字、换 run ID 或拆任务不得抹去累计记录。

每个任务循环最多 6 个候选版本验证（包含初次，不含独立的集成复验）。每个产品任务最多一次自主 replan；任务级验证总轮数最多12（候选与集成验证均计入）。这些是工程默认上限；达到后先总结并退出自动修复，不靠不断换根因名延长循环。

task 级 ledger 独立于 cycle 保存 root-cause/repair/replan/verification 计数；恢复、重建图或换 cycle 不清零。只有新方案和证据支持才能建立新 cycle，并保留旧 cycle 的因果链接；同因修复数仍保留。确有不同机制的新假设须写明与旧假设的差别，硬性任务总轮数和一次 replan 上限始终不变。

限额在派发下一次验证或重新规划前检查；不拦截已完成结果的接收、PASS 投影或检查点写入。最后允许轮次若为集成 SHA 全部必需检查通过，可正常 done；若还需要下一轮验证而额度耗尽，或再次需要 replan 而自主额度已用完，则保存结论转 waiting_input，请用户决定具体新方案/重开额度。此前可继续其他独立 ready 工作。

## 触发与去向
| 触发 | 去向 | 恢复条件 |
|---|---|---|
| 同根因两次修复均失败；或累计候选验证达上限 | replan | Sol 写出原假设为何失效、最小新方案、影响及新验收点；可在原授权内执行的直接推进 |
| 再次需要 replan 且已用完自主额度，或任务验证总轮数达12仍未通过 | waiting_input | 交付具体方案和旧 ledger，获得新的任务范围/额度决定后恢复；换 cycle 不绕过上限；第12轮若已全部通过可正常完成 |
| 内存超门槛且修复无效、关键配置不可得、路径不能证明 | replan；需要改产品边界时 waiting_input | 保留原预算与未通过事实；涉及产品目标变化由用户决定 |
| 越过派工路径、工作树与预期不符、candidate/base 变更 | reconcile | 先检查实际 diff 和所有权，保留用户工作，重建正确基线 |
| 证据缺失、hash 不符、回执 SHA 过期 | verifying / needs_fix | 重新取得当前版本的真实证据；不把证据问题算成产品通过 |
| 缺少 SDK/Windows/授权线路或必要权限 | blocked | 记录所缺前提；能继续的独立工作照常进行，依赖任务不能被标 done |
| 需要远程发布、破坏性操作或产品取舍但缺授权 | waiting_input | 准备具体可审阅结果并请求必要输入；已有授权不重复询问 |
| 用户要求停止 | stopped | 立即停止工具和写入；已有检查点保留，之后获得恢复指令才继续 |
| 已配置的会话预算/节点时限到达，或图步数接近上限 | checkpointed | 在限额内完成最小检查点；用户停止指令优先于补写检查点 |
| 没有 ready task，全部产品任务已 done | complete | 汇总最终 SHA/验收和交付结果 |
| 没有 ready task，但仍有非 done 任务 | waiting_input / blocked / reconcile | 列出依赖与缺失条件，禁止把空队列当完成 |

## 恢复与工具失败
只读、可重复的工具调用遇到瞬时网络错误最多重试一次；产品测试失败、权限拒绝和持久写操作不走通用自动重试。命令结果不明时先查当前状态。尤其不能在 interrupt 恢复后盲目重复启动 agent、提交、集成或发网络请求。

每次执行图调用显式设置 recursion_limit=64（单个任务 cycle，不是一口气跑完 12 个任务）；接近上限先 checkpoint。该技术护栏不替代上述工程退出规则。

预算只使用已配置的真实限制，不编造 token/费用余额。T11 的 24h 观察使用明确的持续时间和当前任务内监测，不把普通命令超时当长期验证完成；不建立会话外 API 消耗循环。

## breakout 交付
task/cycle、failure signature、初次及修复次数、候选 SHA、旧假设、新证据、已尝试方案、仍失败的检查、建议下一动作、是否需要用户决定。普通工程 replan 由 Sol 完成，Astra 不作为自动 fallback。
