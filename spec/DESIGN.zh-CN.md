# 开发设计基线

2026-11-06。本文件汇总设计与实施次序；字段、评分参数和资源数值分别以 contracts/、MEASUREMENTS_AND_SCORING.md、PERFORMANCE.md 为准，不复制多份参数。

## 目标与完成形态
Windows 轻量常驻节点质量面板，自动接入现有 Verge/Mihomo。用户打开窗口即可查看已加载叶子节点、原生历史、指定网站测量、评分理由和出口观察；关闭窗口后继续必要的采集，退出只结束自己的任务。

observer-preview 是中间里程碑；正式 Lite 必须完成 PRODUCT.md 的全部必需能力及 ACCEPTANCE.md 的对应门禁。产品代码、运行时、界面视觉/交互和作者审阅分别给结论，不能互相代替。

## 界面与交互

- 顶部显示宿主连接状态、采集状态、数据新鲜度。实际链路有证据才显示，缺证据时显示未知。核对链路由用户触发。
- 表格每行代表一个节点，独立「评分」列显示算法分数并支持排序。整行底色随结果着色。表中显示节点、当前和收藏标记、宿主原生延迟、逐目标结果、样本、出口观察覆盖和更新时间。
- 卡片是默认视图。每个近方形方块代表一个节点，显示名称、协议、显眼的分数、状态、延迟、样本和逐目标结果。宽度随面板可用空间变化，高度为宽度的 96%。以逻辑像素计，1536 宽六列、1280 宽五列。窗口更窄时减列，内容沿纵向滚动。
- 切换布局保留搜索、筛选、排序和测试勾选。同一份节点快照提供两种布局的分数、颜色和文字。石墨灰作为界面底色，玉绿表示表现好，朱红表示关键目标表现差，琥珀表示服务受限，冷灰表示样本不足或不可比较。卡片用整卡底色、细色标和文字并行呈现。蓝色用于选择和焦点。策略组独立于叶子节点，同节点多组引用只显示一次。
- 卡片间留 20 个逻辑像素，内侧留 16–18 个。雾面用圆角、柔和描边和淡高光表达。节点名、评分和站点结果分组排版。Google、YouTube、OpenAI API、ChatGPT、Anthropic API 的标识配短状态与完整站点名提示。图标从本地加载，缺图时显示文字。
- 打开节点详情后按需查询当前时间窗，展示样本数、测量方法、HTTP 分类、失败、分数封顶原因和 IP 覆盖。关闭窗口释放表格、卡片和绘图资源。
- 支持筛选、排序、收藏、目标权重、历史清理和计划测试开关。计划默认关闭。手动批测先显示请求上限和预计覆盖，执行中可取消。
- 首次接入说明读取范围。采集中断、宿主退出、休眠、数据过期、未测、网络失败和配置缺失各有文字状态。

### 前端验收顺序

1. 使用合成数据出参考图，整理为可编辑的 Figma 表格、五列卡片和六列卡片。用户确认排版、信息密度、颜色和状态表达后，实施正式界面。
2. 在实际 Windows EXE 复核两种视图的同节点分数、色块、样本不足和服务受限显示。切换视图保留筛选与勾选。调整窗口宽度与 DPI 后，卡片能减列并滚动到最后一张，关键文字可读。
3. 在相同负载下验证可视区域渲染、关窗回托盘、重开和退出。按各任务的既有门槛分别记录 EXE 行为、整棵进程树资源和宿主无干扰。Figma 和 Windows EXE 分别留证。

## 产品技术分工
| 部分 | 责任 | 明确边界 |
|---|---|---|
| C# Native AOT 主进程 | 发现、白名单读取、类型投影、调度、SQLite、评分、托盘和节点视图 | 一个节点索引，按窗口查询；不缓存整包宿主响应 |
| Win32 控件 | 窗口、托盘、owner-data ListView | 中文、DPI、键盘及可访问性需要真实验证；Avalonia 是有预算约束的备选 |
| SQLite | 原始事实、持久去重、可合并汇总、IP 与异常事件 | 单写入者、有界批次、保留水位；不保存凭证或完整配置 |
| Go 按需进程 | 指定节点拨号、HTTP 阶段、IP echo | 单节点生命周期，JSONL，取消退出；不启动 hub/listener/TUN |
| LangGraph 开发工具 | 开发状态路由、交接、返工和检查点 | 在 tools/orchestrator/ 实现，与产品隔离，不进入发行包 |

主数据链为宿主白名单读取 → 有界解析 → 节点身份/方法/来源投影 → 去重 → SQLite → 按需节点快照。主动链为用户启用的预算调度 → 单节点有效配置 → Go 测量 → 类型化终态 → 同一存储链。

外部值在所属边界验证一次；内部使用类型明确的记录。不预建跨平台框架、通用插件总线或多层 repository/service 包装。单次用途的简单逻辑保留在调用处。

## 实施关口
1. 开发流程准备：按 workflow/LANGGRAPH.zh-CN.md 完成执行器的离线路由/恢复验收；此前只可称文档设计完成。
2. T00：真实工具链、AOT/SQLite 组合、宿主版本和许可锁定；不能把 GitHub 登录成功等同 T00 完成。
3. T01–T03：先证明测量不漏短命子进程、只读接入真实可行、UI 在同负载下符合预算。
4. T04–T06：节点身份 → 持久去重 → 真实采集/SQLite/表格闭环。
5. T07–T10：评分解释 → 独立拨号 → 网站/IP → 真实端到端；不确定的路径不能进入独立节点排名。
6. T11：24h、干净 Windows、便携包、来源许可与校验和。

产品依赖顺序只认 workflow/tasks.json；此处不是另一套 DAG。

## 优先消除的不确定性
| 假设 | 最小证据 | 不成立时 |
|---|---|---|
| Native AOT + SQLite + 窗口有足够内存余量 | 固定负载 Release 基线及全生命周期峰值 | 两轮同因失败后比较依赖/UI，按 breakout 重新规划 |
| 宿主能提供独立测试所需的有效节点配置 | T00 记录配置来源可得性，T08 验证最小代表线路 | 不索要新订阅，不宣称完整 Lite 可交付 |
| Go dialer 足够小，且不受宿主路径串联影响 | 提取最小依赖；同机指定节点路径证据和主进程合计峰值 | 明确 unsupported/route_unverified；回到方案关口 |
| 稀疏预算能支持可解释排名 | 明示节点数、目标数、样本门槛与覆盖时长 | 标覆盖不足，不能稀释样本门槛以制造榜单 |

T00 可做配置可得性的只读调查；若要提前做 dialer 代码实验，先由协调者明确 runs/ 中的一次性实验范围、网络预算及清理方式，不跳过任务依赖或把实验标为 T08 完成。
