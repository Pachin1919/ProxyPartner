# 资源预算与实测规则
## 预算是产品要求，不是现成成绩
用户要求低于50MB，本版设定：
| 状态 | 私有提交内存目标/门槛 | 检查 |
|---|---:|---|
| 托盘常驻、被动采集+SQLite | 目标≤25MiB | 预热后p95；超过目标需修复/报告，不能自称超轻量达标 |
| 表格打开、100节点/3目标 | 目标≤35MiB | 交互场景p95 |
| 启动/测试/清理任意阶段，全部产品进程 | **硬门槛≤40MiB** | process tree峰值，包含Go/native库 |
| 托盘空闲CPU | 单核等效均值≤0.5% | CPU秒/墙钟秒×100，不除以逻辑核数美化 |
| 重复开关窗口100次 | 句柄/内存无持续泄漏 | 末段与预热基线比较 |
| 连续24h | 末小时中位数比预热首小时≤2MiB | 同负载；仍须≤40MiB；睡眠段排除并说明 |

MB与MiB不要混用。本版均以MiB。记录PrivateBytes（私有提交）、WorkingSet、PrivateWorkingSet可用时、线程/句柄/GDI。宿主原有Mihomo不计入产品预算，但新启动/注入/借壳的任何测量代码都计；同时记录宿主基线与增量，不能把负担转嫁过去。

## 首轮基准
Windows x64 Release Native AOT，非调试器内；记录OS/CPU/RAM/SDK、发布参数、依赖、SHA。三次冷启动，100节点/3目标/7天fixture，再1000节点压力测试；全程检查无监听器、无代理写请求。
托盘10分钟；窗口交互5分钟（滚动/排序/筛选/关闭重开）；SQLite迁移/清理；逐节点Go10轮；取消与错误；最终24h观察。初期15分钟不能冒充24h soak。
外部PowerShell脚本250ms采样仅用于趋势。它可能漏掉短命子进程/尖峰；正式“任意阶段40MiB”必须加Windows Job Object PeakJobMemoryUsed或等价ETW完整生命周期证据，并验证无breakaway进程。不得拿多个进程各自历史峰值相加冒充同时峰值，也不得只测主进程。

## 不允许的优化
不能EmptyWorkingSet/SetProcessWorkingSetSize清工作集；不能每秒GC.Collect；不能把Go改名藏起来；不能停止历史采样；不能把目标和节点数悄悄缩小；不能删失败记录改善评分；不能只测空白窗口。

## 真正要减少的成本
- 不读全量连接和日志；已有原生历史30秒读取，逐条去重，保留最小投影。
- 有界流式JSON解析，源返回未知字段可跳过，内部事件严格校验。整体响应上限8MiB，depth32，单字符串4KiB、节点1000；超限显式失败，不截断伪装成功。
- 一份节点索引，按需分页，UI只维护可见行快照。不开窗口不创建绘图对象，不订阅每秒UI刷新。
- SQLite单写入者，批次最多128条/5秒，内存队列最多512条；达到上限暂停主动测试，不能丢测量终态。原生重复快照允许合并；可丢的进度/调试日志与不可丢的终态分开。
- 缓存按条数和字节双上限，不把所有历史载入内存；仅查询当前时间窗及汇总。
- Go每批只加载一个节点，结束释放/退出；无完整hub、规则集、geo数据库、HTTP服务初始化。

## 性能优化loop
先测baseline → 提出一个具体热点假设 → 一次最小改动 → 同负载A/B交错测量 → 行为不退化且资源下降才保留 → 当前SHA独立验收。代码优化不得与新功能同时合并。两轮同因失败后重新审视UI/依赖，不放宽40MiB。
框架选择失败不是产品已失败；但必须记录失败，不承诺某框架必然达标。
